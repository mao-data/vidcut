  • THE AGENT

    Edits through 31 MCP tools — every operation runs the same validated command path a human edit does. No side doors into the project file.

  • THE BROWSER

    Streams each change over WebSocket the moment it happens. You watch the timeline move, drag anything the AI got wrong, fix a trim, nudge a caption.

  • YOUR CALL

    When the agent calls request_review, writes pause. Approve, or send it back with a note — the agent reads your feedback with get_feedback and keeps working.

  • ON RECORD

    Every step lands in the activity log with undo / redo. A wrong take is one keystroke away from gone — for the AI's edits and for yours.

The actual editor. One process, your machine.

A single Node process on 127.0.0.1:3845 serves the UI, the media, the MCP endpoint and the live socket. Your footage is referenced in place — never uploaded, never copied.

CJK is not an afterthought — captions wrap character-by-character in Chinese, word-by-word in Latin, and leading punctuation never starts a line. Karaoke highlights ride whisper's per-word timestamps.

Known limits, in pencil.

Honesty first — the README says this too, and the repo's EVIDENCE.md pins every verification number to a commit.

  • Karaoke preview strokes look slightly thick. The exported file is correct — one card per word, drawn once. Non-karaoke captions and all overlays are byte-identical between preview and export, guarded by a pixel-level regression test.
  • Very short audio (~4s or less) gets less reliable per-word timestamps — that's whisper's nature; vidcut normalizes but precision drops.
  • Single project, single user, localhost only — by design, for now. it's your editing desk, not a cloud.

Call sheet: rolling in four steps.

No account, no upload, no key. Node 20+, ffmpeg and Python 3 + Pillow do the work; whisper.cpp is optional, for auto-captions.

1
Install the prerequisites
macOS shown — Debian/Ubuntu lines are in the README. Windows runs under WSL. 
brew install ffmpeg
pip3 install pillow
brew install whisper-cpp   # optional — auto-captions only
2
Clone, build, run the demo
The demo generates its own footage — you can try everything before touching your own files. 
git clone https://github.com/mao-data/vidcut.git && cd vidcut
npm install
npm run build -w @vidcut/ui
npm run demo
3
Open the editor
One process, four kinds of traffic: UI, media, MCP, live socket.
open http://127.0.0.1:3845
4
Hand your agent the other chair
Works with Claude Code or any MCP client. Then just talk: “cut the best 20 seconds, caption it karaoke-style, duck the BGM under the voiceover, and show me before you render.” 
claude mcp add --transport http vidcut http://127.0.0.1:3845/mcp
