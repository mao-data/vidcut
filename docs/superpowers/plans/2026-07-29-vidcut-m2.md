# vidcut M2「改得動」Implementation Plan

> **For agentic workers:** 承接 M1（tag `m1-done`）。延續 M1 的 TDD、每任務一 commit、走 `ProjectStore.mutate()` 單一路徑等慣例。

**Goal:** 讓人類能在 UI 上實際編輯——trim 拖拉、片段排序、overlay/caption 文字與位置編輯、undo，以及看到「誰改了什麼」的活動面板。所有編輯走一個**共用命令層**（M3 的 MCP 工具會重用同一層）。

**Architecture:** 新增 `server/src/commands.ts` 命令層：一組具名、經驗證的編輯操作，每個都呼叫 `store.mutate('human'|'ai', ...)`。UI 透過 WS 的 client→server `command` 訊息送出編輯意圖（localhost 直接等 server echo，不做樂觀更新）。活動面板複用「UI 本來就會收到每個 patch（含 source+label）」這個事實，累積成記錄。

**Tech Stack:** 延續 M1。新增 UI 端 pointer-events 拖拉（不引第三方 timeline 元件）。

## Global Constraints

延續 M1 全部約束。新增：

- **命令層是唯一寫入語意來源**：UI 與（未來）MCP 都只能透過 `applyCommand()` 改狀態，不得各自寫 recipe。這確保驗證邏輯單一、DRY。
- **trim 驗證**：`in >= 0`、`duration > 0`、`in + duration <= media.probe.duration`（不得 trim 超出來源）。違反回錯誤、不 mutate。
- **命令失敗不可靜默**：回 `{ok:false, error}`，UI 顯示 toast。

### Task 1: 命令層（server/src/commands.ts）

**Files:** Create `server/src/commands.ts`, `server/test/commands.test.ts`；Modify `shared/src/types.ts`（加 `Command` 型別）。

**Interfaces（M3 MCP 工具也用這個）:**
```ts
export type Command =
  | { name: 'updateClip'; clipId: string; patch: Partial<Pick<VideoClip,'in'|'duration'|'volume'|'label'>> }
  | { name: 'reorderClips'; order: string[] }
  | { name: 'removeClip'; clipId: string }
  | { name: 'updateOverlay'; id: string; patch: Partial<Pick<OverlayItem,'start'|'duration'|'position'>> }
  | { name: 'updateCaption'; id: string; patch: Partial<Pick<CaptionItem,'text'|'start'|'duration'|'style'>> }
  | { name: 'setOverlays'; overlays: OverlayItem[] }
  | { name: 'setCaptions'; captions: CaptionItem[] }
  | { name: 'undo'; steps?: number };

export type CommandResult = { ok: true; version: number } | { ok: false; error: string };
export function applyCommand(store: ProjectStore, source: MutationSource, cmd: Command): CommandResult;
```

驗證規格：`updateClip` 檢查 clip 存在、trim 邊界（見 Global Constraints）；`reorderClips` 檢查 order 是現有 clip id 的排列（同集合、不重不漏）；`removeClip` 檢查存在；`updateOverlay/Caption` 檢查存在與 duration>0；`undo` 直接轉 store.undo。每個成功命令一筆 mutate，label 具描述性（如 `trim No.3`）。

### Task 4: Timeline trim handle 拖拉

**Files:** Create `ui/src/timeline/dragMath.ts` + test；Modify `ui/src/timeline/Timeline.tsx`。

**Interfaces（純函數，可測）:**
```ts
// 拖 in handle：左邊界移動同時改 in 與 duration（保持右邊界不動）
export function trimIn(clip, deltaSec, mediaDuration): {in:number; duration:number};
// 拖 out handle：只改 duration
export function trimOut(clip, deltaSec, mediaDuration): {duration:number};
// 都 clamp 在合法範圍（in>=0, duration>=0.1, in+duration<=mediaDuration）
```

Timeline 的每個 clip 左右各一個 8px handle（`ew-resize`），`onPointerDown`→`setPointerCapture`→`pointermove` 累積 delta→即時預覽（本地 state）→`pointerup` 送 `updateClip` 命令。拖拉時顯示當前 in/duration。

- [ ] Step 1-5: TDD dragMath（邊界 clamp）→ 接上 Timeline handle → commit `feat(m2): timeline trim handles (drag in/out)`
