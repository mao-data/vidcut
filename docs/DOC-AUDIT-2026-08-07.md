### 核對過、確認正確（不改）

抽樣列出比較容易過期、而這次確認仍然成立的：

- 「單一 Node 程序在 :3845 同時服務靜態 UI、`/media`、`/mcp`、`/ws`」——`server/src/app.ts`
  掛 `/media` 與 `ui/dist` 靜態、`server/src/mcp.ts` 掛 `/mcp`（POST/GET/DELETE）、
  `server/src/wsHub.ts` 以 `path: '/ws'` 掛 WS；`server/src/index.ts` 的預設 port 是 3845。
- 「Server 服務的是 `ui/dist`（build 產物）」——`server/src/index.ts` 解析 `../../ui/dist`
  後交給 `express.static`。
- 鐵則三步——`shared/src/types.ts` 的 `Command` 聯集、`server/src/commands.ts` 的驗證與
  apply switch（數值健檢集中在 `numericError`）、`server/src/mcp.ts` 的 31 個
  `registerTool` 與單一份 `instructions`，三層結構與文件描述一致。
- 「`npm run lint` 應乾淨」「`npm run format:check` 應乾淨」——本次實跑，兩者都 exit 0。
  `npm run typecheck` 也 exit 0。
- worktree／`npm install` 那條陷阱——`node_modules/@vidcut/{shared,server,ui}` 確實是指向
  `../../<pkg>` 的 symlink，描述的解析行為與 symlink 結構相符。
- `verify:canvas` 檢查 1 只讀 transform 矩陣的 `a`、`verify:wysiwyg` 自起 :3999 臨時 server
  不碰 demo、`verify:canvas` 會寫回 `projects/demo`、六個 case 的 `exportInk` 各釘什麼、
  原生 `drawtext` 分支已刪且 `render.test.ts` 釘死它不准回來、`scale <= 0`／NaN 的 overlay
  整張不合成、`cardMargin()` 是唯一換算來源、缺 `ink` 的 `.json` 當快取未命中重畫、
  字型候選清單已補 Linux/Windows 路徑且空表時匯出直接失敗——逐條核對後全部屬實。
